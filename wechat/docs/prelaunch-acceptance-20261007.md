PNG/WebP 在现有处理库中仍需要完整解码；处理名额前移只消除了多个请求提前持有原图的风险，没有证明单张大图低于门槛。保持接口关闭，先在部署使用的 Python 3.10 Linux / Pillow 12.2.0 条件下验证低内存处理方案；不得直接上传已暴露风险的 24 MP 样本冲击现有生产函数。不能实现该标准时如实交付容量缺口，不升级资源或悄悄降低图片上限。

本机没有 Docker，现有 WSL 没有安装任何发行版，当前不能运行部署一致的 Linux 隔离测量。本轮没有安装系统环境或启用新的云资源；大图内存阻塞尚未修复。

版本修复覆盖资料、目标、置顶、照片、维修、处置、删除与回收站恢复。上传票据绑定申请时的版本，等待处理名额后及写入事务内再次核对；竞争失败保留旧照片，生成文件进入既有清理队列。明确版本冲突终止原提交编号；未知结果仍以原编号、原版本重试。编辑和关联记录冲突保留表单，只有用户读取并确认最新内容后才采用新版本；资料已保存而照片失败时重试照片，不重复写入资料。

## 云端窗口执行顺序

1. 记录当前套餐周期、剩余额度、实际 QPS、超限付费关闭状态、COS 直传计量归属、已有日志服务和查询保留期。截图或响应应有采集时间；只有 0 元账单不能证明照片免费。任何新增日志开通需要付费则停止，不调用 `createLogService`。
2. 修复多设备覆盖和大图内存问题，重测受影响项。保留单进程、256 MB、60 秒；应用线程数 4 与平台 HTTP 多并发开关分别核对。官方平台多并发默认关闭，不能从 Gunicorn 4 个线程推断 4 个平台请求可并行：[配置说明](https://docs.cloudbase.net/cloud-function/function-configuration/config)。
3. 在两个真实账号分别创建带本轮前缀的测试物品，记录仅含所有者标签与资源 ID 的清单；实际会话、上传表单、签名只在客户端运行内存。交叉覆盖读 / 改 / 删 / 上传 / 提交 / 下载 / 恢复 / 维修 / 处置，核对 404 与 401。
4. `qa-controlled-load.js` 按 1、2、5、10 个逻辑客户端逐级实际调用，每级 50 读、25 写，另核验 10 件测试物品，共计划 310 次，重试另计。必须输入已查证的 QPS 和五项证据、10 个带 `qa-20261007-` 名称前缀的测试 ID、全轮剩余预算；未满足时不发请求。不同逻辑客户端写各自物品，跟随返回版本。未知写入原编号最多重试一次，仍未知则停止。账号切换、窗口到期、预算或错误门槛触发停止，仅返回脱敏记录。脚本尚未云端运行；同时开页、两张照片提交、同物品竞争和双真实账号隔离单独验收。
5. 仅当剩余免费额度允许且内存风险消除时开启最长一小时照片窗口，最多 20 次提交、50,000,000 字节传输。上传、服务端读取、两张衍生图和客户端下载各自计量；双向重复下载不能只算源文件一次。每次调用前预留预算，最终计入失败与重试。
6. 真实小米 K80 Ultra 异常测试，同时及时取应用及平台日志。用请求编号关联登录、上传凭证、提交、下载、失败和重试，检查请求 / 响应 / 异常 / 响应头。仅保存匹配计数、范围、时间和覆盖完整性。CLS 使用当前 [日志查询接口](https://docs.cloudbase.net/api-reference/manager/node/clsLog)，不使用已废弃的函数日志接口。无日志证据保持未通过。
7. 越权成功、凭证泄露、内存不足立即停止；连续一分钟错误率超过 5% 或任何超边界费用也停止。短突发后核对最终错误率、同编号恢复、无重复数据。P95 样本不稳定时列逐次值和最大值，不宣称长期承载能力。
8. 每轮关闭服务器和验收客户端照片开关，注销本轮会话，按本轮清单清理文件与记录并回读；保留既有 1、2 和用户照片测试物品 4，不复用旧清理脚本中固定的 3、5 ID。清理与收尾调用也留出预算。最后核对健康、登录与核心操作继续正常。
