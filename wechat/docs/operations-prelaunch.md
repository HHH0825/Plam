# 上线前维护、恢复与回退

## 现状

正式环境 `cloud1-example`、函数 `palm-api`，HTTP 直连。保留单工作进程、4 个应用线程、256 MB / 60 秒；照片开关关闭。此前单账号 Android 照片验收通过；本轮多用户验收未通过，详见 [验收记录](prelaunch-acceptance-20261007.md)。

## 每日维护

1. 在现有控制台读取日志与资源用量，核对免费配额、有效期、QPS、业务错误、超时、实例异常；优先按业务封装状态计错误，HTTP 200 不代表业务成功。
2. 查看 `palm_storage_gc` 到期积压、最大等待时间、失败次数和脱敏错误码；查看 `palm_items` 的 `purging` 积压，以及过期会话、回执和上传凭证。不要把请求内容、表单或签名复制到日志或报告。
3. 使用已有私有维护入口 `python -m palm.cloud_maintenance`，在可信维护终端临时设置服务端环境；不在仓库或聊天保存凭证。不新增公开清理或诊断接口。
4. 一次最多 40 项逻辑操作、20 秒；每个逻辑操作可能产生多次底层请求。实际底层耗时可能使退出超过软时间预算，必须记录耗时与资源用量；COS 不可用时到期任务保留并退避，不能连续无间隔重跑消耗额度。
5. 读回集合和指定 COS 对象核对删除结果；“处理了 N 项”不代表清理成功。无授权凭证或剩余额度时停止，保留积压缺口。
6. 本轮没有部署自动维护触发器；维护依靠上述私有操作，不能宣称已启用自动定时清理。

## 验收收尾与恢复演练

- 开窗前给测试资源建立清单：轮次、账号 A/B 标签、物品 ID、关联记录 ID、照片路径及原始数量/整数金额，不含会话、签名、密钥或原始个人照片。每轮只清理清单内的本轮资源。
- 写入超时保留原请求编号，通过相同编号重试查明结果；不要盲目新建。回执安全重试期限到期后先核对记录。
- 使用带版本校验的候选客户端：修改已有资料、照片、关联记录和回收站时发送所见版本。`409 ITEM_VERSION_CONFLICT` 且 `retry_same_request=false` 是明确未提交，结束原编号、保留表单并核对最新内容；普通数据库冲突或未知响应不能套用这条规则。已保存资料只重试未完成照片。
- 受控负载脚本每次计划 310 次业务调用（10 次清单核验，四档各 50 读、25 写），重试另计。输入全轮剩余调用预算和已查证的 QPS，预留 400 次收尾；累计账本仅计当前验收客户端执行的调用，其他设备、人工步骤、照片及维护必须同步到脱敏总账。20 次照片提交、50,000,000 字节传输另预留 4 次、10 MB，窗口结束预算不归零。
- 删除进回收站后记录原值，恢复后比较数量、金额、归属、照片版本及关联记录。只用新建测试物品；不能用用户已有物品练习不可逆删除。
- 永久删除会进入 `purging`，不能恢复；验证此前可恢复阶段后，才清理测试物品，逐批运行私有维护。确认元数据和每个指定文件均不存在。
- 每轮结束先关服务器 `PALM_CLOUD_PHOTOS_ENABLED`，再关验收客户端 `CLOUD_PHOTOS_ENABLED`，撤销本轮会话并清空照片缓存。正式客户端始终保持关闭，直到全部门槛通过。
- 保留此前物品 1、2、4。旧清理脚本固定 3、5 的清单属于历史轮次，禁止作为新轮次清理模板直接执行。

## 故障处置与回退

1. 凭证泄露、越权、OOM 或错误率超门槛：立即结束测试并关闭照片。泄露时只保存脱敏计数，撤销受影响会话和上传凭证，必要时在可信控制台轮换受影响密钥，完成日志脱敏后重新验收。
2. 核心资料业务继续使用；照片单独关闭。停服或错误并非通过“改成付费”处理，先核对免费限额和已知功能风险。
3. 候选包回退目标是本轮前已校验的 `palm-api-python310.zip`（SHA-256 `cc0e6b2a80d37d230b7798930618f3cbb8e155c18a6a2113467f31d2592c2ab5`）。维持 `PALM_REQUEST_MODE=direct_http` 及既有环境值；部署后读回代码、核对健康、登录与核心操作，再验证照片仍关闭。
   该旧包没有本轮版本保护。若未来已部署严格校验包，回退到此包会恢复旧表单覆盖风险，不能作为正常多用户写入的长期兜底：先停止验收写入及提审，再准备保留版本保护的兼容修复包并复验。正式上线前须将实际通过的保护版本设为回退基线。当前候选未部署，没有执行回退。
4. 代码回退不还原用户数据库，不清库、不回退已提交用户数据。普通 bridge 旧包有三秒限制和历史登录日志问题，不能自动切换兜底。
5. 所有当前门槛通过才提审。全面公开发布前补 iPhone，并确认现有日志查询、配额、错误率与清理积压的实际监控方式。没有证据时报告缺口，不购买新的监控资源。

## 版本协议部署顺序

候选后端和配套验收客户端一同安排，先核对客户端所有写入路径与 `revision` 字段，再部署后端并验证 404 / 428 / 409 及同编号回执。已有记录缺失版本按 0，不清库或迁移用户数据。旧客户端缺少 `If-Match` 的已有物品写入被 428 拒绝并提示更新，必须在发布说明明确这一兼容边界；新增物品不要求版本。照片保持关闭，待全部内存、成本、日志前提满足再开受控窗口。候选不是正式包，未通过云端验收不能提审。
