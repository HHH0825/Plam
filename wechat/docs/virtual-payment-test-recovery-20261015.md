# 微信查单“数据不存在”的小额测试恢复

用户已确认手机没有付款面板、微信账单没有扣款、MP交易订单为空；本地业务订单为待确认。随后 query_order 返回268490002，errmsg为“数据不存在rid:…”。此响应说明当前查不到对应订单，不能单独证明订单已关闭或绝无后续付款。原支付调用失败的具体原因仍未确认。

## 修复范围

旧流程会在每次购买前核对旧单；查询失败就直接退出，无法重新调用支付并取得最初的失败说明。

- 只有当前服务端测试模式开启、订单所属账号仍在测试名单中、且原订单明确标为小额测试、金额1至100分时，才适用恢复流程。
- 只识别查询订单阶段的268490002加“数据不存在”这一已观察到的明确响应；不将所有268490002、网络失败、签名错误或其他错误视为订单不存在。
- 至少两次实际微信查询，观察间隔至少5秒、原订单创建超过60秒后，可由用户手动重新发起小额测试。快速重复点击被限流的查询不计次数，不会自动发起支付。
- 原订单继续保持pending并保留定时补查。后续若微信返回已支付，仍按原订单核验并发货；没有删除订单、停止查询或把它标成取消。所有正式订单和已发货订单保留原核验要求。
- 前端现在显示脱敏后的支付调用失败说明，包括同步异常和失败回调；数字错误码同样保留。签名、完整signData、attach、订单号、长标识和URL不会显示，也不保存这些诊断参数。

这是仅针对小额测试的人工恢复入口；重复查询的缺失响应并非已付款订单关闭凭据。重新尝试前用户仍应核对手机账单与MP交易订单。如果任何一处显示已支付，先处理原订单，不再支付新单。

## 用户操作

1. 更新已有palm-api函数代码，上传 `wechat/deploy/cloudbase/virtual-payment-test-recovery-20261015/palm-api-test-recovery-python310.zip`。保留全部环境变量、HTTP类型、Python3.10、端口、路由。无需替换通知函数或增加集合、索引。
2. 微信开发者工具重新编译当前小程序，重新生成预览二维码，手机扫码打开。必须更新手机预览，才能看到“支付说明”及恢复提示。
3. 在会员页点“核对待确认订单”，间隔至少10秒再点一次。旧单已创建超过一分钟并达到重复查询条件后，应出现“可手动重新发起小额测试；原单继续核对”。如有多笔旧的待确认测试单，可能需要分别核对；不要批量删除。
4. 确认微信账单和MP交易订单仍无付款后，手动点击一次“小额测试支付”。如出现微信付款面板，只核对商品和0.01元，可取消退出；如希望验证付款，由用户自行确认。
5. 如未出现付款面板，把新提示中“支付错误码…”和“支付说明…”发给维护者。这次取得的是最初支付调用失败的原因，而不只是后续查单提示。

本地测试不等于平台真单验收通过。3秒通知函数超时限制仍未解决，本次没有云端写入或发起付款。待取得实际支付失败说明后继续定位商户配置、商品或客户端参数问题。
