## 配置与部署顺序

1. 新 Python 包支持 `PALM_REQUEST_MODE`：不填写默认为 `bridge`；正式直连填写 `direct_http`。其他数据库、微信凭证、存储变量沿用现有值。保留 `PALM_BRIDGE_SECRET` 以便回退，不给客户端填写密钥。
2. 部署 `wechat/deploy/cloudbase/palm-api-python310.zip`。既有依赖没有改变，也可通过官方增量部署更新 `palm/` 运行代码；完成后下载代码比对。Python 3.10、9000 端口、256 MB、60 秒、Gunicorn 单工作进程继续使用。
3. 保存 Python 环境变量 `PALM_REQUEST_MODE=direct_http` 后，再应用小程序配置模板。模式 `cloud_http_function`，目标硬编码现有环境及 `palm-api`。路径 `/api/mp/...`，不带 `/palm`。
4. 重新编译并重新微信登录。旧 bridge 会话、重试记录与草稿、本地历史数据保留，新模式采用独立范围。

微信 SDK 在 HTTP 400/401/403/404 等响应时只返回错误码，丢弃后端 JSON。为保留页面现有业务错误提示，`direct_http` 模式下业务返回 HTTP 200，并使用 `{palm_http:1,statusCode:<业务状态>,data:<原业务JSON>}`；前端解封后继续按原业务状态码处理。事务提交、请求回执先完成，再封装响应；401 仍会清除当前模式会话。`/healthz` 和 `bridge` 模式保持原形式。

客户端等待最多 20 秒，平台超时和网络错误只显示脱敏信息。不自动切到本地或 bridge。取消只结束本地等待，不承诺撤销已发出的写入；待确认编号保留，重试使用原编号并由后端回执去重。

### 登录响应与日志

当前原生调用在平台日志中产生 `Response ... RetMsg`，其中包含响应正文。直连登录令牌因此改为通过 `X-Palm-Session` 响应头传递，正文不含 `token`；小程序收到并验证响应头后才恢复现有会话结构。正式云端实测响应头存在、正文无令牌、小程序登录成功，重新部署后仍可读取已有物品；15:12 新登录平台日志正文也已核对无令牌。不要在调试控制台打印整个响应、请求头或会话。

修复前测试登录的响应正文可能已进入平台历史日志；本次未删除历史日志，也不能宣称所有旧测试会话已撤销。维护者应在云端管理界面核对历史日志访问与保留期；旧会话最长七天到期。当前照片凭证已改为响应头传递，正文和回执不含签名；实际平台照片响应头日志仍需检查，不能仅通过正文或有效期检查就正式启用。

## 人工分批清理

三十天过期物品即时隐藏且不能恢复。物理清理在维护环境执行，不通过客户端或公开接口：

1. 在维护终端进入 `wechat/backend`，使用现有虚拟环境 Python；在该终端安全配置正式 Python 环境变量，包含 `PALM_REQUEST_MODE=direct_http`，不把密钥发到聊天或写入仓库。
2. 运行 `..\.venv\Scripts\python.exe -m palm.cloud_maintenance`。每次最多 40 项逻辑操作、20 秒，必要时分次执行。
3. 通过云控制台查看 `palm_storage_gc` 的待清理项。失败项保留 `attempts`、`due_at`、脱敏错误码；按 `due_at` 到期后再执行。一次返回处理数量不代表所有文件删除成功。
4. 队列清空、关联记录消失、过期标记保留才算该批处理完成；不要清空整个数据库或存储桶。

本阶段不部署自动清理函数，不依赖普通云函数超过三秒运行。
