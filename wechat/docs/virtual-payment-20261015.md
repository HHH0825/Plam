# 猫爪会员虚拟支付接入与验收

2026-10-15。代码接入已实现，默认关闭购买；未部署云函数、修改生产数据、配置真实密钥或发起真实付款。本文以用户粘贴的官方个人主体指引、query_order完整字段及云开发消息推送说明为协议依据；微信文档站受访问策略限制，没有假称在线读到原网页。

## 已实现的流程

套餐为月390分、季990分、年2990分，只做`short_series_goods`道具直购，不做代币、自动续费或自动扣款。服务器固定金额、数量、商品映射与env=0；每次新下单生成31位唯一单号。购买前重新wx.login，由服务器code2Session取得sessionKey，核对openid与当前账户一致后即时计算两套签名。sessionKey、AppKey、微信登录code和payData不写入订单或客户端重试存储。

客户端校验基础库≥2.19.2、接口可用、iOS微信≥8.0.68（包括恰好此版本）。iOS还有单独开关，简称和支付资格未验证时保持关闭。开发者工具模拟器不拉起支付，需手机验证。支付回调只启动服务器核对，会员身份始终读取服务器。连续点击合并；未知付款结果保留订单号并提供核对入口；重启或下单响应丢失可从服务器最近订单找回。

云函数`palm-pay-notify`接收两个平台事件，向Python服务转发最少字段，使用独立密钥签名原始请求体和时间戳。Python不接受公开XML通知，也不把客户端上送事件当成付款凭据：每次通过服务器access_token和pay_sig向微信query_order核实订单。核对业务单号、正式环境env_type=1、现金支付类型0/7、订单金额/已付金额/剩余金额及微信内部单号；仅状态2、3、4允许发货。状态0、1、5、6、7、9、10不授予权益，退款状态8不重新发货。

发货、微信单号去重记录、会员续期同事务提交，SQLite与CloudBase均支持。同一平台单号不能跨订单或跨账户使用，同一业务订单不能换一个平台单号再次发货。自然月按北京时间计算，月底取目标月末；续费从当前到期时间与现在的较晚者开始。

消息通知丢失时，5分钟定时器补查，每批最多8单，35秒软截止；失败和未付款记录也后移，CloudBase用游标轮转避免固定头部订单阻塞。已开通订单每天核对退款，退款通知到达时即时核对。现阶段不会主动调用退款接口；安卓开发者可在MP后台处理退款，iOS由用户向Apple申请。

**退款行为**：全额退款依据微信原支付单left_fee=0核实，撤销该单带来的会员时长，保留原有权益基线及其他有效续费，重复通知不重复扣减。部分退款标记`partial_refund`供人工核对，已有权益暂保留，界面明确显示待核对；没有擅自约定部分退款的会员时长折算规则。旧导出报告和用户记录不删除。

云开发直连的payData使用`X-Palm-Pay-Data`响应头传递，避免进入返回JSON内容日志；上线仍需实际检查平台是否记录该响应头，禁止自行输出完整请求、支付参数、通知、密钥或微信响应。

## 你需要准备什么

你已确认个人主体、大陆身份证、工具类目、认证备案及虚拟支付开通完成。接下来在MP后台已开通的“虚拟支付”页面找到OfferID和**现网AppKey**，并创建三种道具，价格分别390、990、2990分。把各道具ID填入服务器配置；不要把AppKey或AppSecret发到聊天、写到前端或提交Git。AppID沿用该小程序现有AppID；AppSecret沿用服务器微信登录配置。不同账号后台栏目可能不同，找不到时只提供已遮挡密钥的页面截图。

iOS需要在MP后台完成简称及实际显示的iOS开放条件，再将`PALM_PAY_IOS_ENABLED`设为1；“可以配置”不等于已经完成。全终端月限额10万元。按所提供的指引，安卓费率1%、结算T+3；iOS费率12%、结算约45–60天。安卓退款可由开发者在后台操作；iOS退款由Apple决定。支付180天以内退款退还手续费，超过180天不退手续费。上线前以后台实际规则复核。

服务器环境变量模板见`deploy/cloudbase/api/env.example.json`，回调函数模板见`deploy/cloudbase/pay-notify/env.example.json`。两个函数共享一条独立随机`PALM_PAY_NOTIFY_SECRET`，不复用AppKey、AppSecret或现有业务转发密钥。保持`PALM_PAY_ENABLED=0`，直到部署与受控真单验证准备就绪。可在服务端运行`tools/check-payment-config.py`，只输出配置是否存在，不输出任何密钥值；存在不等于已经验证正确。

## 接口

- `GET /api/mp/membership`：含`payment_open`、`ios_payment_open`。缺凭据或开关关闭时不开放下单，免费功能照常。
- `POST /api/mp/pay/order`：仅接受`plan_id`、新`code`。返回持久化订单及签名payData；云开发直连的payData经响应头传递，由传输层还原。
- `GET /api/mp/pay/orders`、`GET /api/mp/pay/orders/<outTradeNo>`：仅本人最近20单或单笔状态，不返回openid、attach或支付签名。
- `POST /api/mp/pay/query`：仅本人`out_trade_no`，主动向微信核实并补发；3秒限频窗口，不能由客户端改变状态。
- `POST /payments/wechat/notify`：内部签名转发专用，兼容云函数消息与补查任务；未签名、过期或核实失败不返回成功。
