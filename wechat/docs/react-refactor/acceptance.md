# 收纳位置试点实施与验收

返回[需求与架构](README.md)，参见[逐文件施工表](file-contracts.md)与[试点验收结果](results.md)。

## 1. 施工顺序和负责人交接

| 阶段 | 工作与负责人 | 交付与进入下一阶段的条件 |
|---|---|---|
| M0 原生基线 | D 复现构建，E 核对原生行为。选定能同时运行现有回归和试点的 Node 版本。用标准 npm Terser 试编，比较微信编译、运行结果、压缩策略及包体。 | 两个干净工作目录独立构建，逻辑路径与内容哈希一致。记录 26 路由、包体、回归、原生真机基线和合成测试资料。结果有差异时逐项解释并复测。 |
| M1 契约冻结 | A 写 TypeScript 类型、解析器与合成样例，E 写契约测试。集成负责人复核业务与现有 UI 对照。 | 固定 V1 导出、输入字段、动作列表、缺省值与非法输入行为。签名和测试供所有组使用。 |
| M2 最小编译试验 | D 在忽略的试点工作区接入最小组件，配合 B 验证单路由和双向传输。 | 微信开发者工具实际打开原路由。Model 更新可见，事件只回传一次，未触发真实业务写入。微信编译通过且依赖闭包全部属于收纳分包。记录工具／基础库版本和真实生成路径。 |
| M3 独立实现 | B 提取控制器、桥与原生外壳，C 用同一契约和合成模型实现 React 展示，D 完成组装与检查，E 继续补回归。 | B 用模拟意图独立验证，C 用模型和收集操作的回调独立验证。单组无法编译时先核对依赖输入与契约，不绕过守卫。 |
| M4 集成候选 | D 先生成原生，再组装试点，E 对比 V1–V6。集成负责人只处理跨组变更。 | 从干净克隆完成自动构建，通过开发者工具和隔离真机验收，保留原生候选作回退。若某项失败，修复后重新运行对应门槛。 |
| M5 扩展评审 | 项目维护者根据维护成本、包体、性能及真机结果决定试点去留。 | 有证据再决定是否采用试点。正式上传、审核和发布为单独操作。 |

M0 的重点是把已经能在作者电脑上运行的工程变成其他维护者能复刻的工程。M2 检查实际编译与分包约束，先于大规模视图实现。M2 若失败，优先找出生成依赖或微信组件边界，原生仍可交付。后续如希望换成全 Taro 或重做路由，由维护者另行决定。应用层无需等待 React 才能继续维护。

每组交接提交包含文件清单、接口版本、可运行命令和结果。当需要改共享契约时，集成负责人先接受具体现象和测试，再同时更新契约、消费方和样例。现有工作区的用户文件和线上资料无需参与试点。

## 2. 命令和产物

| 施工后命令 | 预期结果 |
|---|---|
| `npm ci --prefix wechat/tools --ignore-scripts` | 安装原生构建的锁定工具。 |
| `node wechat/tools/build-local-variants.cjs` | 生成原生 `test-results/local-builds/local-source`、`local` 和 `local-manifest.json`。 |
| `npm ci --prefix wechat/react-pilot --ignore-scripts` | 安装试点的锁定工具。 |
| `npm run check --prefix wechat/react-pilot` | 运行 TypeScript 类型检查。 |
| `npm run dev:weapp --prefix wechat/react-pilot` | 使用 `taro build native-components --type weapp --watch` 监听组件并更新试点暂存输出。 |
| `npm run build:weapp --prefix wechat/react-pilot` | 运行类型检查、编译 CJS 契约和生产组件，执行当次原生构建并通过 `build-react-pilot.cjs` 组装。 |
| `node --test wechat/tests/*.test.cjs` | 在本机已有当次构建时运行原生、契约、桥接与组装回归。CI 安装及构建在前，测试在后。 |

日常联调先跑完整 `build:weapp`，将候选项目导入微信开发者工具。watch 为组件开发提供编译反馈，合并回微信项目仍走完整 `build:weapp`，确保装入的是同一批次的输出。开发与生产使用同一个锁文件。生成产物、source map、临时 ZIP 和工具生成的 AppID 副本均应位于忽略跟踪的目录。

试点输出为 `test-results/local-builds/local-react-pilot-source`、`local-react-pilot` 和 `local-react-pilot-manifest.json`，内含微信开发者工具可导入的完整项目。两份原生目录与两份试点目录各有明确用途。原生输出继续沿用现有检查，React 组装只写试点路径。试点 source 保留原生可编辑源码及未压缩桥接脚本，试点最终包沿用原生已压缩项目和 Taro 生产组件，新增原生脚本按基线工具处理。Taro 组件无需二次压缩，保证它与验证过的生产产物一致。

组装时核对原生项目输入及清单哈希。复制收纳视图依赖的完整闭包至 `pages/storage-locations/react-build/`，包括同一组件所需的模板、样式与运行资源。共享 CJS 放在收纳分包内的 `react-build/contracts/storage-locations.js`，保持原生 adapter 的相对引用。桥与投影放到收纳分包下，页面引用固定路径。只有目录布局适配和静态路径改写可以在组装完成，由 M2 确认确切生成文件规则。构建须检查所有 JS、组件 JSON、WXSS、WXML 声明和静态资源引用能解析，且没有指向源码、其他分包或意外根文件。保留现有合法的原生公共组件和资源引用。所有候选写入受控暂存目录，成功后发布清单作为可用标记。失败退出非零，不留下可被当成本次成功的新清单。

清单沿用原生的项目目录、输入、逐文件字节和 SHA256，并增加试点依赖来源、入口路由、工具版本、两种包体及检查结论。路径使用可公开的仓库相对地址。重复构建通过比较内容与归一化清单验证，忽略用于记录的本机绝对输出路径。原生网络检查保持有效。试点额外审计调用点及生成闭包，框架如果带入通用 API 定义，逐项核对调用能否从试点入口触达，并以断网和拦截计数证明业务无服务器流量。发现业务网络、登录或支付路径仍可达就拦截候选。

## 3. 验收矩阵

| 编号 | 场景与验证方法 | 通过标准 |
|---|---|---|
| V1 原生及兼容 | 从干净克隆先构建后执行全部既有前端测试。对照两份候选的 `app.json`、分包、主入口、四个 tab、26 路由和分享落地。 | 原生对照全部通过，试点保留相同路由和入口。试点以外页面的发布文件与本次原生对照一致。 |
| V2 视图契约与交互 | 用合成模型检查 23 个意图、版本不匹配、非法字段、0 与 null、未就绪、空列表、查询无匹配、输入校验、禁用和单次派发。运行 320／390／430／768 CSS 像素宽度、放大字号、键盘和减少动态效果检查。 | 展示和原生业务入口一致，窄屏关键按钮仍有完整点击区域。组件的渲染、重挂和状态变化均无写入副作用。真实事件进入正确方法。 |
| V3 控制器与异常 | 有效期变化、当前 scope 更换、快退、重复点击、确认取消、旧照片绑定错误、资料读失败、409/428、已删除物品和移动至空位置。 | 只有有效确认能写一次。冲突后保留可核对的选择，刷新后需用户再确认。照片错误只作用于当前展示的图。已过期的请求、确认、投影和回调无副作用。 |
| V4 构建与依赖 | 核对入口依赖闭包、文件清单、哈希、包体与版本锁。在 Windows 和 CI 上至少各生成一次，包含微信开发者工具对实际候选的编译。 | 源码和正式构建主包都 ≤1,450,000 字节，分包符合现有阈值。试点的原生非收纳文件和主包与当次原生对照逐文件一致。源码和运行产物无公开凭证。 |
| V5 真机与性能 | 同一私有测试 AppID 和合成资料，安卓与苹果各运行原生和试点。冷启动、缓存启动、打开收纳大列表、搜索和批量移动各对照，记录环境、样本数、中位数及慢样本。代码已下载后断网验证核心读写和统计，核对正常联网运行时的业务请求计数。 | 原生首屏没有加载 Taro，收纳可操作且没有可复现的异常。启动无可复现退化，收纳性能记录供发布决定；业务服务器请求为 0。 |
| V6 升级、降级与恢复 | 私有测试 AppID 造一组带照片、回收站、账目、退款和付款的资料。原生建档 → 候选读写 → 原生回退 → 导出至文件传输助手 → 从聊天选文件在另一台设备恢复。附带取消、损坏包、空间或权限失败样例。 | 文件选择和保存可用，恢复前核对、替换确认及数据保全如预期。对照记录数量、关键关联、权限状态、金额统计和照片文件 SHA256。失败后原资料可用。 |

V4 的自动编译与 V5、V6 的真机证据分别归档。模拟器成功仅记为模拟器成功；真机不可用时明确标记未实测，并继续保留原生候选。运行表中所有设备场景使用测试 AppID 和合成资料。保留原生发布包备查；试点回退直接重建或选原生候选，使用同一数据格式与同一小程序身份。复测升级与回退的顺序时分别记录原生和候选构建的提交与哈希。

## 4. 最终交付记录模板

| 记录字段 | 内容 |
|---|---|
| 源码版本 | 原生基线、候选源码提交、契约版本和锁文件哈希 |
| 构建证据 | CI 结果、Node/npm/Taro/微信工具版本、候选路径及清单 SHA256 |
