# 收纳位置试点验收结果

记录日期 2026-11-27。测试使用隔离模拟器项目和合成物品。项目设定及验收步骤见[架构方案](README.md)与[验收矩阵](acceptance.md)。

## 构建与行为

- Node.js 24.18.0、npm 11.16.0、Taro 4.3.3、Webpack 5.91.0。依赖用锁文件重新安装。替换原生压缩器后，两个独立的干净源码副本各生成 502 个文件，哈希逐项一致。接入控制器后完成新的原生与试点构建。
- 全部 591 项前端回归通过。收纳用例包括入口参数、23 个操作映射、重复确认、冲突刷新、旧资料库响应、图片回退和分包引用。
- 微信开发者工具 2.02.2609231 编译通过。最小组件里的单个模拟器 tap 事件只回传一次，更新后的原生模型重新渲染到按钮。完整试点在宽度 366 的模拟器里通过新建位置、搜索和移动物品。重复触发移动只弹出一次确认，重新读取能看到已保存的位置。拦截计数中的业务网络调用为 0。
- 公开产物使用 `touristappid`。实际开发者工具预览使用本机隔离副本，合成数据写到单独的文件目录。

| 产物 | 源码主包 B | 压缩主包 B | 源码收纳分包 B | 压缩收纳分包 B |
|---|---:|---:|---:|---:|
| 原生本地版 | 1,389,431 | 1,331,895 | 25,822 | 21,752 |
| React 试点 | 1,389,431 | 1,331,895 | 326,228 | 320,003 |

主包和收纳以外的文件逐项一致。两个主包均在 1,450,000 字节预算内，收纳分包符合现有 1.9 MiB 阈值。更换 Terser 前的原生压缩主包为 1,336,598 字节。这个差值属于构建工具差异。

## 模拟器性能

用 60 条合成物品，各采集五次。应用入口为同一模拟器会话内重新进入物品页，收纳与搜索分别取模型就绪和筛选结果更新的时间。计时含模拟器导航与轮询开销，记录中位数和最慢样本，单位为毫秒。

| 场景 | 原生中位数／最慢 | React 中位数／最慢 |
|---|---:|---:|
| 会话中重新进入物品页 | 2,310 / 2,728 | 1,350 / 1,485 |
| 打开包含 60 件物品的收纳详情 | 1,787 / 2,083 | 2,936 / 3,221 |
| 搜索并更新结果 | 47 / 49 | 71 / 73 |

主包内容相同，入口计时的波动不作为启动提速结论。该样本中，React 收纳详情比原生慢约 1.15 秒，继续保留原生为默认构建。真机冷启动和缓存启动需要另测。

## 交付与回退

产物、逐文件哈希清单与 ZIP 的 SHA256 在 `test-results/local-builds/`。原生可导入目录为 `local/`，试点可导入目录为 `local-react-pilot/`。回退时改用同批次原生目录，沿用原有本机资料和备份协议。

待验项包括安卓和苹果真机升级、降级、从文件传输助手导出及从聊天导入，以及 320／390／430／768 宽度、放大字号、软键盘的逐项视觉验收。当前证据支持继续本机试点。正式上传、审核和发布由项目维护者决定。
