# 猫爪物帐：Android 与 iPhone 照片验收

当前已接入现有微信 CloudBase 环境，后端为 Python HTTP 云函数，客户端通过 `wx.cloud.callHTTPFunction` 调用。2026-10-07 持机人报告小米 K80 Ultra 的相册选图、拍照、保存后重进详情及替换均正常，电脑端真实云端流程也已完成。临时照片接口现已关闭。第二个真实账号、iPhone、平台照片签名日志保护及下表其他项目仍待验收；完整证据见 [本轮照片验收记录](photo-acceptance-20261007.md)。

## 准备照片验收预览

1. 保留环境 `cloud1-example`、正式数据库与现有桶，沿用已登记的 uploadFile / downloadFile COS 域名。无需另外购买服务器或域名。
2. 验收期间的服务端照片开关须与 [云端照片部署说明](cloud-photos-cos.md) 的待验项目一起核对。本轮用户明确允许临时开启，审批后完成验收并恢复关闭。下一轮需要再次授权受限验收窗口；未开通时不将上传失败误判为手机故障。
3. 使用独立验收预览，客户端指向现有 HTTP 云函数，真实微信登录，照片开关仅在受控验收期间开启；不上传发布正式版。测试新建明确标注的验收物品，不修改既有物品和本地历史记录。
4. Android / iPhone 持机人扫码打开预览，手动处理相机、相册和系统授权，再执行下表。开发者工具无法代替真实手机拍照和系统权限检查。
5. 先测相册图片保存及重新进入后的原图、缩略图，再测拍照、替换、删除、断网重试和换账号。只有完整实测及证据齐全后才记为通过。

## 请求与首次显示记录

固定同一组至少六件带照片物品：首次打开清单，滚动经过全部照片；进入一件详情再返回，重复同一路径。记录照片请求数与响应体字节数、首次照片出现和清晰照片替换的体感或录屏时间。清单请求 `size=thumb`，详情与编辑请求 `size=full`；缓存有效的返回不应再次下载同版本缩略图。

弱网下先看占位与布局，再看错误重试。不要将后端响应耗时或电脑缓存回放耗时当作手机显示耗时。样例仅代表这组图片；不同图片、网络和手机的收益会不同。
