# 猫爪会员小额真实支付测试

本次提供独立测试商品和服务端账号限制，默认关闭。没有修改云端配置或发起付款。标准套餐仍为390／990／2990分；测试模式只允许指定账号购买一个低价月会员，其他账号暂时不能下单。成功支付仍发放一个自然月会员，没有自动续费。不是沙箱或模拟付款，env仍为0。

## 按顺序操作

1. 暂时将 `palm-api` 的 `PALM_PAY_ENABLED` 设为 `0`，防止准备期间误下单；如果此前有扣款不确定的订单，先核对原订单。
2. 微信公众平台 → 虚拟支付 → 基本配置 → 道具配置 → 添加道具。类型选择普通道具，关联关系选择自定义。创建独立道具：

   | 字段 | 内容 |
   |---|---|
   | 道具ID | `catpaw_test_month` |
   | 道具名称 | 猫爪月会员测试 |
   | 道具价格（元） | `0.01` |
   | 图片 | 原会员商品图片即可，200×200且小于200KB |
   | 备注 | 小额测试一个月会员 |

   提交审核，按照后台流程发布现网，确认出现在“线上版本”。页面截图没有给出最低价格，本地测试也不能证明平台接受0.01元；若后台不接受，使用它允许的更小价格，例如允许0.10元时填0.10，服务端对应填10分。测试配置只接受1至100分。不要修改正式三个道具的价格。
3. 更新已有 `palm-api` 的代码，上传本次新包：`wechat/deploy/cloudbase/virtual-payment-small-test-20261015/palm-api-small-test-python310.zip`。保留已有HTTP类型、Python3.10、9000端口、路由及全部环境变量。旧包不支持以下测试配置。无需替换 `palm-pay-notify`，本次也不增加数据库集合或索引。
4. 在微信开发者工具里重新编译本项目，用准备付款的同一微信账号登录。在小程序调试器的Console（控制台）执行 `getApp().globalData.user.id`，只读取自己的数字账号ID。不要读取或截图整个用户对象、token、密钥。若没有数字，先登录；不要猜ID。也可在业务库 `palm_users` 确认自己账户记录的 `id` 字段，不是 `_id` 或openid。
5. 编辑 `palm-api` 环境变量，保留原来的支付凭据和转发配置，增加：

   | 变量名 | 值 |
   |---|---|
   | `PALM_PAY_TEST_ENABLED` | `1` |
   | `PALM_PAY_TEST_USER_IDS` | 上一步自己的数字ID，例如确认是7才填 `7`；多个账号用英文逗号且不带空格 |
   | `PALM_PAY_TEST_PRODUCT` | `catpaw_test_month`，必须与本次独立道具ID相同 |
   | `PALM_PAY_TEST_PRICE_CENTS` | `1`，表示1分＝0.01元；若后台填0.10元，这里填 `10` |
   | `PALM_PAY_IOS_ENABLED` | `0`，先验证安卓 |
   | `PALM_PAY_ENABLED` | 最后设为 `1` |

   测试账号配置错误、缺少测试道具、价格不是1至100的整数等情况会关闭下单，不会回退到正式价收费。测试账号只能购买月会员；不能通过客户端传入低价解锁年会员。非测试账号仍可正常使用免费功能、查看原订单。
6. 用开发者工具生成新的预览二维码，安卓手机扫码，以刚才指定的微信账号登录。进入“我的 → 猫爪会员”：只应有“月会员测试”，显示 `¥0.01`，并提示真实扣款、发放一个月会员。如果出现正式三套餐、金额不符或订阅未开放，先检查上述步骤，不要付款。
7. 点击“小额测试支付”。微信支付面板也必须显示 `0.01元` 和本次测试商品；金额不一致就取消。这是真实付款，由你确认。先只付一次；如扣款后未开通，点击“核对待确认订单”，在MP交易订单和业务库查同一单，勿重复付款。
8. 验证MP订单金额、业务订单金额（1分）、微信单号一致；业务订单为 `fulfilled`，会员到期日更新。重开页面、重复核对不能重复延长。业务订单 `test_payment=true` 用于辨认测试订单。可在MP后台对该安卓测试订单申请全额退款，再核对退款到账、业务订单 `refunded` 和对应会员时长撤销；发起退款不等于退款已到账。

## 测试结束

先将 `PALM_PAY_ENABLED=0`，再将 `PALM_PAY_TEST_ENABLED=0`。刷新后应恢复3.9元/月、9.9元/季、29.9元/年。确认正式三个商品已发布、服务端ID正确、发货及退款流程验收通过后，再决定开启正式购买。关闭购买或测试模式不会阻止已创建订单继续核对、补发和退款；处理时使用订单保存的商品和金额，不套用当前套餐价。可在后台下架测试商品。

## 当前限制与验收记录

- 本地已验证两种数据库的测试账号隔离、错误配置禁止下单、签名中的整数分、标准价恢复、关闭测试后的旧单发货／退款、重复发货幂等；前端验证0.01展示和页面价格改变时阻止拉起支付。
- 商品审核／最低金额／现网上架、手机真实付款、消息推送、到账和退款均需在平台实测，本地测试不能替代。
- `palm-pay-notify` 目前3秒超时，曾有首次调用超时。空订单查单测试成功不代表有订单时也能在3秒内完成；小额支付只能降低测试金额，不能消除冷启动和网络超时。原通知转发及批量查单没有改成3秒以内保证完成的实现。先确认两条消息推送已启用、定时查单实际运行，再进行这笔小额测试，不视为正式上线验收通过。
- 原「部署前检查清单」尚未完成的线上项目继续待验收。现网测试支付后请保留订单号，避免凭前端失败提示判断是否扣款。
