# 手机未出现付款面板时的诊断更新

用户反馈：手机点击“小额测试支付”，没有出现付款面板，没有微信账单扣款记录，却收到“微信支付结果暂时无法核实”。仅凭旧提示无法确认根因。

## 已确认的代码行为

- 点击购买前先核对未完成的旧单。如果该次查单失败，会直接显示旧的统一提示，并不调用微信支付。
- 新单返回后调用微信支付；此前支付调用的失败详情被忽略，继续查单。查单又失败时仍显示同一提示。
- 当前提示来自服务端 `PaymentProviderError`，可能在获取access_token、调用query_order或核对订单数据时出现。不能据此断定密钥错误、商品未发布、通知超时或已经扣款。

## 本次调整

- 服务端返回固定阶段、固定错误类别及微信数字错误码；云端日志同样只记录这三项。不会返回或记录密钥、sessionKey、签名、请求URL、微信原始响应或用户openid。
- 前端支付调用失败时保留数字错误码，并在查单失败提示中区分支付调用和服务端核对。仍以独立服务端确认发货，不凭前端回调开会员。
- 保留原订单用于核对，没有取消不确定订单、自动删除订单或放宽重新付款限制。错误码仅帮助诊断，未改变微信接口、签名、环境或支付金额。

## 用户操作

1. 只更新已有 `palm-api` 代码，上传 `wechat/deploy/cloudbase/virtual-payment-diagnostics-20261015/palm-api-payment-diagnostics-python310.zip`。保留现有全部环境变量、HTTP类型、Python3.10、端口和路由。小额测试配置沿用此前设置，不替换 `palm-pay-notify`。
2. 微信开发者工具重新编译，重新生成预览二维码，手机扫码打开更新后的版本。
3. 先点击“核对待确认订单”，将完整的新提示（阶段和数字错误码）提供给维护者。如果需查看服务端日志，打开 `palm-api` 日志，寻找 `Payment verification unavailable stage=... reason=... wechat_code=...`。不要提供完整请求、密钥或未脱敏日志。
4. 根据实际错误码再决定处理步骤；未核实前不反复点购买。若后续出现支付面板，仅在商品与0.01元均正确时由用户自行确认。

本地测试及打包不代表现网验证通过。3秒通知函数的已知限制没有在本次解决，支付和退款仍待真实验收。本次没有云端写入或付款。

## 268490002后续诊断

用户收到 `查询微信订单；微信错误码268490002`，并表示手机没有付款面板和扣款记录，MP后台交易订单为空。按用户提供的官方错误码表，该码表示请求参数字段错误，具体原因需看 `errmsg`；不能仅凭此码判断订单不存在或允许重新付款。

原诊断版本未返回微信的字段错误说明，信息不足。补充版本只增加经过脱敏、最长180字的微信错误说明，移除已知密钥、access_token、签名、openid、业务单号、长标识和URL。服务器日志仍只记录固定阶段、类别和数字错误码，不记录这段说明。

用户更新已有 `palm-api`，上传 `wechat/deploy/cloudbase/virtual-payment-error-detail-20261015/palm-api-payment-error-detail-python310.zip`，保留全部配置。此步仅变更服务端错误说明；如果手机已经是前一诊断版，可以直接退出再进入会员页，无需再次修改小程序页面或通知函数。然后点“核对待确认订单”，提供包含“微信说明”的新提示。仍不删除原订单、不将参数错误当成未付款凭据，不重复发起支付。

“购买记录”指小程序“我的 → 猫爪会员”页面底部、与“核对待确认订单”并排的右侧按钮。里面显示本地业务订单号，可用于与MP交易订单对照。
