# 猫爪会员：自己操作部署的步骤

本说明对应2026-10-15的本地代码。用户已同意部署，由用户在自己的后台操作。本文、压缩包和资源清单都不表示线上已经部署或验收成功。本次只准备文件，没有修改线上服务。

2026-10-15补充：首次真单可以先按[小额测试说明](virtual-payment-small-test-20261015.md)配置独立低价道具及指定账号限制，使用其中的新包；不直接执行本文的3.9元付款步骤。

## 先找到两个上传包

| 用途 | 本地文件 | 操作 |
|---|---|---|
| 更新现有后端 | `wechat/deploy/cloudbase/virtual-payment-20261015/palm-api-virtual-payment-python310.zip` | 更新已有的 `palm-api` HTTP函数 |
| 新增支付通知接收 | `wechat/deploy/cloudbase/virtual-payment-20261015/palm-pay-notify.zip` | 新建普通／事件函数 `palm-pay-notify` |
| 数据库集合与索引完整清单 | 同目录 `database-prerequisites.json` | 对照后台，只补缺失项目 |
| 每5分钟查单的配置 | 同目录 `timer-config.json` | 给通知函数配置定时触发器 |

使用上面专用目录里的包。上层目录原来的 `palm-api-python310.zip` 是旧版，不包含本次支付实现。不要重新压缩整个项目，也不要把Windows的 `.venv` 上传。新后端包约11.43MiB，已包含原来的Linux Python3.10依赖、当前40份运行文件和启动脚本；通知包约1.6KiB，不需要安装额外依赖。

## 1. 确认环境并备份

1. 打开[云开发控制台](https://tcb.cloud.tencent.com/)，选择小程序对应的已有环境：`cloud1-example`。
2. 在“云函数”找到 `palm-api`，将当前代码下载留作回退；将现有环境变量安全备份在自己可控的位置，不发到聊天或放进项目。
3. 对已有业务数据库做可恢复的备份／导出，至少覆盖物品、流水、账户、会员、计划。确认能找到备份，再更新服务。
4. 后续所有操作仍在这个环境，暂时保持支付关闭。不需要再购买一台独立服务器。

## 2. 在小程序后台准备三种商品

登录[微信公众平台](https://mp.weixin.qq.com/)，进入已经开通的“虚拟支付”。不同账号的栏目名称可能不同，以实际已开通的支付入口为准。

1. 找到 **OfferID** 和 **现网AppKey**。AppKey仅填服务器环境变量，不能放到小程序代码；它不是AppSecret，也不是云开发API Key。
2. 在道具／商品管理中创建三种会员道具。下面的道具ID是建议值，如果后台已经创建，直接使用已有真实ID。

| 名称 | 建议道具ID | 单价，元 | 单价，分 | 权益时长 |
|---|---|---:|---:|---|
| 猫爪月会员 | `catpaw_vip_month` | 3.90 | 390 | 1个自然月 |
| 猫爪季会员 | `catpaw_vip_quarter` | 9.90 | 990 | 3个自然月 |
| 猫爪年会员 | `catpaw_vip_year` | 29.90 | 2990 | 12个自然月 |

后台价格输入框若标“元”，填3.90、9.90、29.90；若标“分”，填390、990、2990。服务器发送的金额始终为整数分。季度9.9元是整季价格，年度29.9元是整年价格。按后台要求完成商品提交／审核／上架，确认商品在正式环境可购买。

只做道具直购、到期手动续费，不选择代币充值或自动续费订阅。iOS先不开：等后台简称及iOS相关开放要求全部完成后，再按第10步单独验证。

## 3. 检查数据库，只补缺失集合和索引

到云开发“数据库”查看现有 `palm_` 集合。**以 `palm-api` 现有 `CLOUDBASE_DB_INSTANCE` 和 `CLOUDBASE_DB_NAME` 配置为准**；本地正式配置为实例 `(default)`、数据库 `(default)`。控制台出现 `tnt-example` 本身不能证明选错数据库，不要仅凭名称判断。先确认所选库就是当前 `palm-api` 存放 `palm_users`、`palm_items` 的业务库。

完整清单是 `database-prerequisites.json`：共22个集合，21个业务组合索引。既有集合／相同字段顺序的索引已存在就跳过，不删除、不重建、不导入空表覆盖旧数据。所有集合的客户端权限选 **无权限／仅管理员（ADMINONLY）**；服务器仍可访问。

若以前的记账、会员更新尚未部署，需要补建下面九个集合，而不只是支付的两个：

| 集合 | 要补的组合索引：字段按此顺序，全部升序、非唯一 |
|---|---|
| `palm_wishlist` | `user_id, _id` |
| `palm_fixed_expenses` | `user_id, _id`；`user_id, item_id, _id` |
| `palm_expense_payments` | `user_id, _id`；`user_id, item_id, _id` |
| `palm_storage_locations` | `user_id, _id` |
| `palm_ledger_entries` | `user_id, _id` |
| `palm_ledger_settings` | 无额外索引 |
| `palm_member_documents` | `user_id, kind, _id` |
| `palm_pay_orders` | `user_id, _id`；`next_query_at, _id` |
| `palm_pay_deliveries` | 无额外索引，利用内置唯一 `_id` 去重 |

还需在已有 `palm_items` 补 `user_id, storage_location_id, _id`，若已经有就跳过。各索引建议名称见JSON；字段、顺序和非唯一属性才是核对重点。等待索引创建完成后继续。本步骤不需要手工新增会员或订单记录，也不迁移历史流水。

## 4. 给两个函数准备同一条内部转发密钥

这是自己生成的一条随机口令，不从微信购买或申请，不复用AppKey。可以用密码管理器生成64位随机字符；或在电脑PowerShell运行下面命令，生成64位随机十六进制字符并放进剪贴板，不在终端打印：

```powershell
$paySecretBytes = New-Object byte[] 32
$paySecretRng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$paySecretRng.GetBytes($paySecretBytes)
$paySecretRng.Dispose()
([BitConverter]::ToString($paySecretBytes)).Replace('-', '').ToLowerInvariant() | Set-Clipboard
```

把同一条值安全保存，并分别粘贴到两个函数的 `PALM_PAY_NOTIFY_SECRET`。不要把值发到聊天、截图或项目文件中。两个函数填写完成后清空剪贴板。

## 5. 更新已有的 palm-api

在云开发控制台 → 云函数 → `palm-api`：

1. **保留现有函数名称、HTTP类型、Python3.10、9000端口、256MB内存、60秒超时以及已有路由。** 不新建同名服务，不选择普通Node.js函数。
2. 在配置／环境变量中，保留原来所有配置，新增或更新下面八项；保存配置。不要用 `api/env.example.json` 整份覆盖，那里有占位内容和照片关闭示例。

| 环境变量名 | 值 |
|---|---|
| `PALM_PAY_ENABLED` | `0`，先关闭下单 |
| `PALM_PAY_IOS_ENABLED` | `0`，先关闭iOS购买 |
| `PALM_PAY_OFFER_ID` | 你后台真实OfferID |
| `PALM_PAY_APP_KEY` | 你后台**现网**AppKey |
| `PALM_PAY_PRODUCT_MONTH` | 月会员真实道具ID |
| `PALM_PAY_PRODUCT_QUARTER` | 季会员真实道具ID |
| `PALM_PAY_PRODUCT_YEAR` | 年会员真实道具ID |
| `PALM_PAY_NOTIFY_SECRET` | 第4步生成的随机口令 |

不要额外添加“价格变量”，价格已固定在服务端代码中。核对已有 `PALM_WECHAT_APP_ID=touristappid`、AppSecret对应本小程序、`PALM_WECHAT_DEV_LOGIN=0`、`PALM_STORAGE_BACKEND=cloudbase`、`PALM_REQUEST_MODE=direct_http`。保留数据库管理员API Key、COS照片密钥和照片开关等已有值。

3. 在代码页选择“上传ZIP包／本地上传”，上传 **`palm-api-virtual-payment-python310.zip`**，完成保存／部署并等待函数恢复正常。Python依赖已经包含在包中，不需要在电脑重新安装或在线编辑12MB代码包。[CloudBase Python部署说明](https://docs.cloudbase.net/cloud-function/quickstart/httpfunc/python)
4. 浏览器打开现有网关健康地址：

   `https://cloud-function.example.invalid/palm/healthz`

   应返回 `{"ok":true}`。再用开发者工具预览小程序，检查真实微信登录、旧物品、记账、图片和会员页；会员按钮此时仍应显示“订阅即将开放”。健康检查只证明服务启动，不证明数据库和支付正常。

## 6. 新建 palm-pay-notify

云函数 → 新建，选择空白普通／事件云函数，设置：

| 配置 | 值 |
|---|---|
| 函数名 | `palm-pay-notify` |
| 类型 | 普通／事件云函数，**不是HTTP云函数** |
| 运行环境 | `Nodejs20.19` |
| 执行入口 | `index.main` |
| 内存 | 256MB |
| 超时 | 60秒 |
| 上传包 | `palm-pay-notify.zip` |

如果后台不允许设置60秒，先保持支付关闭，提供不含密钥的限制提示；不能沿用旧桥接函数的3秒超时。本实现的定时查单可能需要数十秒，不要直接按3秒发布。

添加三个环境变量并保存部署：

| 环境变量名 | 值 |
|---|---|
| `PALM_PAY_RELAY_URL` | `https://cloud-function.example.invalid/palm/payments/wechat/notify` |
| `PALM_PAY_RELAY_HOST` | `cloud-function.example.invalid` |
| `PALM_PAY_NOTIFY_SECRET` | 与 `palm-api` 完全相同的随机口令 |

HOST只有域名，不加 `https://` 或斜杠；URL保留完整路径。通知函数不需要AppKey、AppSecret或数据库管理员密钥，不添加公网HTTP触发器。

在云函数“权限控制”中，**保留现有整个环境的规则**，只合并这一项：

```json
"palm-pay-notify": { "invoke": false }
```

这是合并片段，不能把它单独当整个规则文件覆盖保存；保留原有 `*` 与 `palm-api` 等规则。它用于禁止小程序客户端直接调用支付通知函数，管理员和定时任务仍可运行。平台支付消息推送是否送达必须在第9步真单验证。[CloudBase函数安全规则](https://docs.cloudbase.net/cloud-function/security-rules)

## 7. 绑定发货和退款消息

按你提供的官方消息推送指引，在微信开发者工具打开此项目 → 云开发 → 设置 → 其他设置 → 消息推送：

1. 选择推送模式“云函数”。
2. 添加一条：消息类型 `event`，事件类型 **`xpay_goods_deliver_notify`**，环境选择本次环境，函数选择 **`palm-pay-notify`**。
3. 再添加一条：消息类型 `event`，事件类型 **`xpay_refund_notify`**，环境和函数相同。
4. 保存，核对两条配置均生效；保留已有其他消息配置。

这里不选择代币或自动续费事件。不需要把上一步的内部RELAY_URL填到MP后台XML消息URL框：我们用云开发消息接收，那个URL只供两个函数之间签名转发，不是微信XML回调接收器。

## 8. 开启每5分钟自动核对订单

在 `palm-pay-notify` 的定时触发器配置中新增：

- 名称：**`palm-pay-reconcile`**，必须完全一致。
- 类型：`timer`。
- Cron：**`0 */5 * * * * *`**，七段，表示每5分钟一次。

如果页面要求配置JSON，使用本次目录的 `timer-config.json`。不要填成 `*/5 * * * * * *`，那会每5秒运行。[CloudBase定时触发器说明](https://docs.cloudbase.net/cloud-function/timer-trigger)

部署后，可以在这个新函数的控制台“测试”中使用以下管理端测试事件：

```json
{"Type":"Timer","TriggerName":"palm-pay-reconcile"}
```

没有订单时应返回 `{"ErrCode":0,"ErrMsg":"success"}`。这验证转发地址、共享密钥、数据库基本访问；**不代表已验证微信真实查单**。不要伪造一条“付款成功”事件来当验收。再等两个5分钟周期，看调用记录确认实际定时触发，不超时。通知代码不输出订单或密钥日志，不能要求日志中出现完整微信响应。

## 9. 用安卓手机做第一笔真实付款

1. 保持未向公众发布新客户端。通过开发者工具当前项目的“预览／真机调试”或已上传的体验版，用具备相应权限的安卓微信登录；模拟器不能验收支付。如果平台对支付要求特定版本渠道，按后台要求操作，不以绕过限制的方式测试。
2. 确认前八步完成后，把 **`palm-api` 的 `PALM_PAY_ENABLED` 改为 `1`**，保存生效。iOS开关仍为0。此开关控制所有用户的新下单，不是单账号测试开关；安排短测试时段，验证失败就恢复0。
3. 重新打开小程序“我的 → 猫爪会员”。先选择**月会员3.9元**，核对微信支付面板的商品和金额，再由你在手机确认付款。这是现网真付款，不是模拟或沙箱；不为测试临时把390分改成1分。
4. 支付后确认会员身份更新、到期日增加一个自然月，会员功能可用。若暂未更新，使用页面的订单核对入口，先查已有订单，不重复付款。
5. 云端核对：`palm-pay-notify` 确实收到并成功处理发货事件；`palm_pay_orders` 对应业务单状态为 `fulfilled`，有 `wx_order_id`；`palm_pay_deliveries` 只有该微信单号对应的一条去重记录；MP交易订单的商品与金额为月会员390分，微信单号一致。不要手工改状态或到期日来让检查通过。
6. 关闭重开小程序、重复点击核对订单，会员到期日不能再增加。取消另一笔未付款订单不能开会员。
7. 用测试账号再做一笔受控订单验证补单：暂时只暂停**发货消息这条绑定**，保持定时器、退款消息和服务可用；付款后退出小程序，不进行客户端查单。等待1–2个5分钟周期，确认定时器补发且只开通一次，然后立刻恢复发货消息绑定。仅在没有其他真实用户付款的受控阶段进行。
8. 如需要验证退款，在MP后台对安卓测试单办理**全额退款**，等待退款通知／查单确认后，核对订单 `refunded`、该笔会员时长撤销且其他有效续费仍保留。退款不会删除物品和账目。部分退款当前进入人工核对，不拿它替代全额退款验收。

首次支付可能在调用微信接口、消息实际字段、响应头传递或平台配置上暴露问题。本地测试不能替代真单。若扣款成功而未开会员，先记录业务单号和时间、关新下单开关，保留通知和定时查单，不能删除订单或再付款“试一下”。

部署时还需检查平台没有记录 `X-Palm-Pay-Data` 完整响应头；代码不主动打印支付参数。若日志包含支付签名，先关闭新下单并调整日志策略，再继续验收。服务器获取access_token如受微信IP白名单限制，按真实云端出口配置，不能填写电脑的局域网IP或把微信API改为客户端调用。

## 10. iOS验收、发布与回退

1. 在MP后台完成小程序简称以及实际列出的iOS支付要求。确认可用后，设置 `palm-api` 的 `PALM_PAY_IOS_ENABLED=1`。
2. 用微信 **8.0.68及以上** 的iPhone单独做一笔真单，核对价格、通知、会员、订单及账单。未通过时恢复iOS开关0，安卓可继续单独验收。
3. 免费功能、会员功能、安卓、iOS、通知、定时补单和退款均通过后，再用微信开发者工具“上传”客户端，按MP后台要求填写版本说明、提审和发布。按平台实际要求提供会员购买及退款说明。
4. 如果上线后异常，先把 `PALM_PAY_ENABLED=0`；保留当前支付通知处理及定时查单处理已付款订单。不要盲目把后端回滚成没有支付接口的旧包，否则已付款用户可能无法补发。需要回退代码时应先处理所有未完成支付单并保留支付处理能力。

按用户提供的接入指引：全终端月支付限额10万元；Android费率1%、T+3结算，iOS费率12%、约45–60天结算；安卓开发者后台退款，iOS用户向Apple申请。180天以内退款退还手续费，超过180天不退还。以上在实际后台上线时再核对；不以“已经购买数字内容”为由承诺一概不退款。
